# Zoe's folder

Two things live here: the weather-data pipeline that built the project's shared
`.nc` files, and a per-site salmon-spawning model pipeline built on top of them.

## Setup

```bash
python -m pip install -r requirements.txt
```

Pinned to what's currently verified working (Python 3.14.6). See
`requirements.txt` for notes on loosening versions.

## Structure

| Path | What it is |
|---|---|
| `src/` | **Current** salmon-spawning pipeline: load → features → target → model, single site at a time. |
| `Old processing/` | Weather-data pipeline that built `../../data/Global_weather/*.nc` (PNWNAmet + Daymet + NARR splice, bias correction, monthly aggregates). Already run; kept for provenance and re-derivation, not re-run routinely. |
| `data/interim/`, `data/processed/` | Generated by `src/`. Not raw data — safe to delete and regenerate. |
| `outputs/` | Metrics, plots, and the pickled model for whichever site is currently configured in `src/config.py`. |
| `outputs_by_site/<site>/` | Snapshots of `outputs/` (plus its own `data/interim`+`processed`) saved off per site after a run, so results for multiple sites can coexist. |
| `figures/` | Standalone plots (e.g. `jul_aug_temp_precip_maps.png` from `src/plot_jul_aug_maps.py`). |
| `handoff/` | `HANDOFF.md` (how the weather `.nc` was built) and `R_HANDOFF.md` (the R/Shiny weather-layer app) — read these before touching either pipeline. |
| `notebooks/` | Currently empty. |

## Running the salmon-spawning pipeline

The pipeline is scoped to **one site at a time**, selected by editing
`src/config.py` (`SITE_NAME`, `FLOW_CSV`, `SALMON_CSV`, `SITE_LAT`/`LON`,
`FLOW_STATION_ID`). It is not parameterized by CLI flag — swap the constants,
then re-run all four steps in order:

```bash
cd src
python load.py       # -> ../data/interim/daily_env.parquet, spawning.parquet
                      #    ../outputs/data_quality_report.md
python features.py   # -> ../data/interim/daily_features.parquet
python target.py     # -> ../data/processed/features.parquet
python model.py      # -> ../outputs/metrics.md, model_env_only.pkl, plots
```

After a run, copy `outputs/` and `data/{interim,processed}/` into
`outputs_by_site/<site>/` (and `outputs_by_site/<site>_data/`) if you want to
keep that site's results before running the next site.

Notes baked into the code (see each file's docstring for why):
- Splits are **leave-one-year-out** (`GroupKFold` on `year`), never random
  k-fold — adjacent days within a season are near-identical, so random folds
  leak and inflate scores (`model.py`).
- Features are computed on the full continuous daily record *before* seasonal
  subsetting, so trailing 7/14-day windows have lookback into the prior
  season (`features.py`).
- The target asks "does the run start today, given it hasn't yet" — see
  `target.py` for why the alternative framings don't work for this data.
- `SEED = 42` in `config.py` for reproducible RF runs.

## Running the weather-data pipeline

Only needed if the shared `.nc` files must be rebuilt or extended. Full
context, data sources, rejected approaches, and known gotchas are in
`handoff/HANDOFF.md`. Short version:

```bash
cd "Old processing"
python build_merged_weather.py   # PNWNAmet + Daymet splice (~35 min cold; needs ~/.netrc Earthdata login)
python fill_ocean_cells.py       # NARR marine fill
python bias_correct_land.py      # land bias correction -- NOT idempotent, see HANDOFF.md
```

`build_monthly_weather.py`, `extract_monthly_prcp.py`, and
`extract_t_max_monthly.py` derive the monthly-aggregate `.nc` files from the
daily merged output above; run after it, not before.
